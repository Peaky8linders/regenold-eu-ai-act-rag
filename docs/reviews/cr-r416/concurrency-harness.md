## A judge's CLI default model is frozen at first import, not at invocation

- file: `evals/judge/legal_v2.py:149`
- bug: `_DEFAULT_MODEL = os.environ.get("REGENOLD_JUDGE_MODEL", "claude-sonnet-4-6")` is evaluated once, at module import time, and then only ever read from the module-level name (`evals/judge/legal_v2.py:1848`, `p.add_argument("--model", default=_DEFAULT_MODEL)`). Previously this was a plain string constant with no dependency on `os.environ`; the diff makes correctness depend on **when** the module is first imported relative to when `REGENOLD_JUDGE_MODEL` is set in the process environment.
- impact: In any long-lived process that imports `evals.judge.legal_v2` before `REGENOLD_JUDGE_MODEL` is set or changed (e.g. an orchestration/harness script that imports this module early, or a test suite where `sys.modules` caches the import from an earlier test file), a later `os.environ["REGENOLD_JUDGE_MODEL"] = "..."` (or `monkeypatch.setenv(...)`) has no effect on `_DEFAULT_MODEL`/the CLI's `--model` default — callers relying on the env var to steer the default judge model silently get the stale value baked in at first import, with no error or warning. Plain `python -m evals.judge.legal_v2` invocations are unaffected (env is set before the process starts), so this only bites same-process reuse, which is exactly the pattern the rest of this diff (`gate_validity.ArmProbe`, `easyhard_ab` reusing `evals.judge.runner`'s module-level `_JUDGE_MODEL`) is built around.
- fix: Resolve the default lazily inside `main()` (`os.environ.get("REGENOLD_JUDGE_MODEL", "claude-sonnet-4-6")` at `argparse` construction time, or as a `default=None` + post-parse fallback) instead of caching it in a module-level constant evaluated at import.
