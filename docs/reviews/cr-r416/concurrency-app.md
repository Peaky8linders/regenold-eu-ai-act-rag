## Bedrock denoiser leg can increment the Stage-2 PRIMARY transport counters and make a dead run look live
- file: `app/routes/regenold.py:7877` (with `app/llm/bedrock_client.py:1239`, `:1256`, `:1405`)
- bug: The new `_BedrockDenoiserProvider.complete` calls `complete_with_fallback`. That function has a last-resort step, `_try_wrapper_fallback`, which runs when every Bedrock model in the chain returns a skippable error (entitlement 403 or `api_validation` 400). That step calls `stage2_policy.record_attempt(STAGE2_PRIMARY)` and `record_result(STAGE2_PRIMARY, ok=True)`. Those counters are process-global. So a Stage-0 query rewrite now counts as a successful Stage-2 primary completion. Before this change, no denoiser provider touched these counters. The hop also rebuilds the request without `timeout_seconds`, so the denoiser's 3.0 s fail-fast becomes the wrapper's default 60 s.
- impact: `easyhard_ab._transport_liveness` treats `primary_ok > 0` as "live" (`evals/harness/easyhard_ab.py:743`). `gate_validity` reads the same counters for arm attribution. Suppose a multi-turn row's rewrite hops, for example because `REGENOLD_DENOISER_MODEL_BEDROCK` names a 403 model such as `eu.anthropic.claude-sonnet-5`. Then a run where Stage-2 never landed can clear the R398 liveness guard, which is the false-green class that guard exists to block. It also puts a wrapper call of up to 60 s on the multi-turn critical path. You would see `bedrock_wrapper_fallback_used` log lines on denoiser calls and a `primary_ok` higher than the number of Stage-2 calls.
- fix: For the denoiser, call `get_bedrock_provider().complete(...)` directly, or pass a flag that skips `_try_wrapper_fallback`. At minimum, only record the counters when the caller is the Stage-2 path. Forward `timeout_seconds` into the wrapper hop.
- confidence: 62

## Challenge-focus block calls `is_challenge_turn` before the history is flattened, so the pattern family can never fire there

## Root-question recovery skips a coreferent disputed turn and re-answers an older, different question
- file: `app/routes/regenold.py:8459`–`8470`, `:8497`
- bug: `_root_q` is the most recent prior user turn that passes `_live_turn_is_self_contained`. That check needs at least 6 words, no coreference and an AI-Act anchor, so any coreferent turn is skipped. The comment says "from Turn 1", but the selection is really "latest self-contained turn". Take `[u1 "Is emotion recognition at work prohibited under Art. 5?", a1, u2 "what about deployers?", a2, u3 "I don't think this is correct"]`: the disputed answer is a2, yet u2 is skipped and u1 becomes `resolved_question`. The result also sets `self_contained_focus=True`, which drops the prior-turn anchors that would have carried u2's context.
- impact: A pushback on a follow-up turn is answered as a re-ask of an earlier question. Refs and prose move to the wrong provision set, which hurts hard-mode turn-1 reference retention. It happens without any warning, because the block's broad `except` and the trace note both look normal.
- fix: Use the last prior user turn (`dialogue[last_user_idx-1]` or the nearest `role=="user"`). If it is not self-contained, either don't take this path (fall through to the denoiser, which resolves coreference) or combine it with its antecedent. Don't pick an earlier turn instead.
- confidence: 65
