## `_parse_judge_json`'s schema-key allowlist is stale for the three newly-added judge axes
- file: `evals/judge/runner.py:571-574` (allowlist), used against schemas defined at `evals/judge/legal_v2.py:592-596` (`answer_crag_fine`), `evals/judge/legal_v2.py:651-653` (`answer_faithfulness`), `evals/judge/legal_v2.py:684-686` (`answer_relevancy`)
- bug: The Pass-4 fallback branch of `_parse_judge_json` only accepts a candidate JSON object if it contains at least one of a fixed set of keys: `{"verdict", "winner", "propositions", "classifications", "citations", "sentence_count", "issues", "criteria_analysis", "candidate_a_audit"}` (`runner.py:571-574`, filter at `runner.py:634`). This diff adds three new judge axes whose prompts explicitly instruct the model to respond with schemas that use none of those keys: `answer_crag_fine` returns `{"score","class","rationale","missing","hallucinated"}`, `answer_faithfulness` returns `{"claims", "failure_mode"}`, `answer_relevancy` returns `{"relevancy","rationale","failure_mode"}`. Pass 4 exists specifically to recover a valid JSON object when the model "prepends a thinking sentence" or otherwise adds prose around the JSON (per the function's own docstring) — exactly the situation where passes 1-3 (fence match, whole-text parse, literal_eval) fail. For these three axes, when that situation occurs, Pass 4 finds the correct balanced-brace object but discards it because none of its keys are in `target_keys`, and the function falls through to `return {"judge_error": "unbalanced_json", ...}`.
- impact: Any live run of `answer_crag_fine`/`answer_faithfulness`/`answer_relevancy` will silently lose rows to `judge_error: unbalanced_json` whenever the judge model doesn't emit perfectly clean, unwrapped JSON — degrading `_aggregate`'s denominators and truthfulness/faithfulness/relevancy means without any visible warning (a `judge_error` row is treated as a legitimate "error", not surfaced as a parser defect). This is invisible in the test suite: `tests/test_judge_adversarial_remedies.py::TestResilientJsonParser` only exercises `"verdict"`/`"winner"`/`"factual_score"` keyed payloads (all already in `target_keys`), and `tests/test_r359_crag_fine_axis.py` / `tests/test_r360_hypa_ref_free_axes.py` call `_postprocess_answer_crag_fine`/etc. directly with already-parsed dicts, never through `_parse_judge_json`, so the gap is untested.
- fix: Either make `target_keys` a union that includes the new axes' schema keys (`score`, `class`, `relevancy`, `claims`), or derive the acceptance test from "the candidate isn't one of the known truncated-array element shapes" alone rather than requiring membership in a hardcoded, per-axis key allowlist that must be kept in sync by hand every time a new judge axis is added.
- confidence: 80
