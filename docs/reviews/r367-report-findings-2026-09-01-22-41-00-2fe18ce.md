## Critical Issues

### [C1] Cross-Clause Negation Bleed in `_TIER_DENIAL_RE` Drops Asserted Tiers
- **File:** `app/engines/stage2_fidelity.py:183-205`
- **Bug:** `_TIER_DENIAL_RE` patterns used `[^.!?]{0,40}?` between the negation cue (`not`, `neither`, `nor`) and the tier label (`high-risk`). In compound sentences like `"The system is not prohibited under Article 5, but is high-risk under Article 6."`, the `not` across the comma matched `_TIER_DENIAL_RE["high_risk"]`, falsely excluding `high_risk` from the contract set.
- **Impact:** `len(contract)` dropped below 2, disabling the cross-tier fidelity guard on compound sentences.
- **Fix:** Tightened `_TIER_DENIAL_RE` regexes to require the negation cue to immediately precede the tier label (with optional modifiers) and not bridge across punctuation. Added unit tests for compound sentences.
- **Confidence:** High (95%)
- **Found by:** Error Handling & Edge Cases Reviewer, Logic & Correctness Reviewer

## Important Issues

### [I1] False Truncation on Markdown Table Wrapped in XML Channel Tags
- **File:** `app/engines/_graph_rag_impl.py:250-280`
- **Bug:** Markdown table row check was evaluated on raw text before peeling trailing XML channel closing tags (`</answer>`). If an answer ended with a markdown table inside `<answer>...</answer>`, `last_line` was `</answer>`, and after peeling `</answer>`, the trailing pipe `|` was flagged as a mid-clause cut (`tail[-1] not in ".!?"`).
- **Impact:** Complete answers ending in markdown tables with XML channel tags were discarded and triggered fallback.
- **Fix:** Moved markdown table row check to after the XML channel and wrapper peeling loop. Added regression unit test.
- **Confidence:** High (95%)
- **Found by:** Logic & Correctness Reviewer

### [I2] Coverage Clause Duplication Assertion in `test_r320_live_sentence_cap.py`
- **File:** `tests/test_r320_live_sentence_cap.py:192-202`
- **Bug:** Test did an exact source code string check for `user_message += USER_ANSWER_COVERAGE_CLAUSE` which was updated to use the selector function `user_message += user_answer_coverage_clause()`.
- **Impact:** Test suite failure during regression run.
- **Fix:** Updated test assertion to check for `user_message += user_answer_coverage_clause()`.
- **Confidence:** High (99%)
- **Found by:** Contract & Integration Reviewer, Test Runner
