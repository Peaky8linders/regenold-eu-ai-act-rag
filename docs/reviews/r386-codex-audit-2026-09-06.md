**1. High priority: head preservation does not guarantee a correct paragraph**

`app/routes/regenold.py:3392` ranks paragraphs using twice the question-token overlap plus answer-token overlap. It commits to the top paragraph when two numerical thresholds pass. There is no requirement that the selected paragraph contain the operative rule asked about, or cover the multiple rules in a broad answer. Longer paragraphs have more opportunities to overlap. The answer's aggregate vote can dominate despite its lower per-token weight.

Concrete reproduction from `tests/test_intent_pruning_integration.py:56`:

| Question | Deepener OFF | Deepener ON |
| --- | --- | --- |
| What's the maximum penalty for using prohibited AI? | `Article 99` | `Article 99.7` |

In the Regulation text used by this repository, Article 99(3) supplies the prohibited-practices penalty ceiling. Article 99(7) supplies factors for deciding individual fines. The new citation therefore fails to point to the rule requested. This is independently supported by the [official Regulation text](https://eur-lex.europa.eu/eli/reg/2024/1689/oj/eng).

The deterministic answer in this fixture already drifts into prohibited-practice examples with the flag OFF. That answer defect predates this change; the new, narrower wrong citation is attributable to the deepener. This is exactly the risk of using an already-drifting answer to select a coordinate.

Replacing the test's positive assertion with `Article 99 in heads(refs)` would make `99.7` pass. Repair or conservatively abstain on unsupported narrowing before classifying this test as migration-only. Add a coordinate-specific regression test; retaining the head is safer than inventing precision.

**2. High priority: the migration conflicts with explicit negative assertions**

The worklist contains tests whose intended granularity is unambiguous:

| Test | Existing contract | Reproduced ON output |
| --- | --- | --- |
| `test_r133_prose_subpoints.py:227`, `test_route_keeps_head_when_question_does_not_name_the_subpoint` | Keep `Article 6`; explicitly forbid every `Article 6.*` | `Article 6.3` |
| `test_r115_followups.py:134`, `test_q11_default_wire_collapses_the_enumeration_dump` | Keep `Annex IV`; explicitly forbid every `Annex IV.*` | `Annex IV.2` |
| `test_r268_board65_4.py:94`, `test_references_carry_article_65_4` | Explicitly require the Article 65 cluster to fold to its bare head | Requires a deliberate contract decision, not merely a presence-check rewrite |

The first two are direct counterexamples to the handoff's premise. A positive head projection cannot make either test pass while preserving its negative assertion. The later deepening pass undoes a grain decision made by the earlier granularity/collapse passes.

Apply the handoff's own stop condition: distinguish legitimate head-presence migrations from intentional product-contract changes. If these older contracts are superseded, document that decision and retain independent coverage of the previous pass and rollback regime. Do not describe it as intent-preserving string normalization.

Also distinguish two kinds of negative assertions. A cluster exclusion should reject every child (`Article 111.*` as well as `Article 111`). A parent-only exclusion beside required leaves must continue to exclude only the parent. Neither “leave every negative string untouched” nor “project every negative to heads” is universally correct.

Use the existing semantic/intent decisions or carry an explicit granularity decision through the route. A single winning paragraph is not automatically a replacement for a provision cited to support several rules. Add these already-known paraphrases before expanding coverage.

**4. Medium priority: R384 changed KB content without updating its identity**

`app/data/kb.py:33` remains `2024.1689.v21`, while R384 changed the Article 74 summary at line 1434. The two snapshot tests fail with expected hash `86d303bd...` versus current hash `28b07158...`.

These are pre-existing relative to R386, but are unfinished work within the recent changes under review. The version enters the engine cache key and the graph's code-versus-stored-KB comparison (`app/main.py:581`). Leaving it unchanged prevents those identity checks from recognizing the new content. This does not prove that a running instance currently serves stale answers; it proves the version contract was broken.

Resolve the KB version/snapshot together through the repository's applicable version-change procedure. Do not suppress the tests, change the seeder version unnecessarily, or enable automatic seeding.

**5. Medium priority: saved scorers are useful reports, but not yet enforceable gates**

I injected a deliberately broken candidate in memory: both gates printed FAIL (`+171` and `+99` additional missing heads), yet the script returned normally with exit code zero. No source file was modified for this check.

The advertised `live_ab_analyse.py` fails as checked in: it opens `mingold_rows.jsonl` and `live_ab_grain.json`, rather than the committed artifact names. `score_mingold.py` has a related stale input filename. The scripts also hardcode this Windows checkout path. I reproduced the live figures only by redirecting the stale filenames to the committed artifacts in memory.

Make artifact paths relative to the script/repository, reject missing/duplicate rows and insufficient sample counts, and return a failing exit status when an enforced gate fails. Preserve per-row losses alongside aggregate gains.

The proxy builder has sensible contamination controls: it never sees the candidate answers or citations. Its limitations still matter:

- Both grain samples share a single candidate-head selection. Their intersection cannot recover a provision omitted in that first step, and systematically removes disputed second references.
- `mingold.py:174` supplies only the first 6,000 characters of each candidate provision. Eight of the 53 selected heads exceed that limit, affecting 35 of the 110 questions, including candidates from Articles 5, 26, 74 and Annex III. “Verbatim” describes the supplied text, not its completeness.
- Eleven questions have no accepted key. Neither sample agreement nor exclusion of unstable rows establishes correctness on those cases.
- The committed five validation rows contain five predicted references against seven official expected references: three exact sets and two subsets. `rg_024` lacks Annex III; `rg_105` lacks Article 111.1. The documentation's “precision 7/7” is not the count in the committed artifact; these five predictions are correct, but two expected references are absent.
- The old pruning loss of 19 and the newer loss of one come from different corpora as well as different gold definitions (129 probe rows versus 99 official-batch rows). Their difference cannot be attributed solely to gold minimality without annotating and scoring the same rows under both schemes.

The unchanged head metric is expected by construction, even for a systematically wrong paragraph selector. The handoff's stronger claim that a wrong coordinate “costs nothing” is true only for particular metric cases where both candidates already miss the strict key. It is not a semantic safety property.

**Recommended next sequence**

1. Keep the deepener default OFF; classify the 27 assertions without assuming the answer in advance. Address the wrong-coordinate and explicit-granularity conflicts first.
2. Fix the scorer's reproducibility and failure signaling, and add paragraph-specific negative cases. Preserve its useful saved captures.
3. Complete the R384 KB version bookkeeping separately, and investigate the remaining full-suite order dependence in place.
4. Once behavior is resolved, migrate only legitimate head-presence contracts, retain order/count/exclusion guarantees, and run the two-arm full suite and required evaluation procedures. Use the deny-list form for any eventual default-ON flag.
5. Then pursue additional grain coverage. Neo4j's `.letter` supplies a coordinate, not a better relevance signal. Directly making graph nodes the source of emitted citations would conflict with the repository's graph-is-non-citable invariant. The local provision corpus already has letter and nesting parsers; validate selections against that authoritative text and evaluate letter-level errors explicitly.

The recent work contains useful fixes and a promising optimization. The next step is a small set of behavior and evidence repairs before migration, not an automatic default flip justified by head invariance.
