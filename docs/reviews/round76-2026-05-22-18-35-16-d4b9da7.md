## Important Issues

### [A] Multi-turn items inherit representativeness from the wrong scenario
- **File:** `evals/bench/representative_100.py:201` (build) / `:414` (lookup)
- **Bug:** `build_pool` builds multi-turn chains from `scenarios[::stride][:50]`
  (stride≈6), so `mt_001` derives from `scenarios[6]` (`sc_006`). But
  `categorize_pool` does `base = it.item_id.replace("mt_", "sc_")` →
  `mt_001`→`sc_001`, the wrong scenario. 49 of 50 multi-turn items read a
  mismatched representativeness rating.
- **Impact:** `select_representative` ranks multi-turn items by
  representativeness; the wrong 20 chains can be promoted. Undermines the
  "unbiased representative" guarantee.
- **Fix:** Store the source scenario id on `PoolItem` at build time; key the
  cache lookup off it.
- **Confidence:** High (2 specialists + verifier)
- **Found by:** Logic & Correctness, Error Handling

### [D] `_parse_json_array` first-bracket heuristic drops whole batches
- **File:** `evals/bench/representative_100.py:270-285`
- **Bug:** `s.find("[")` parses from the first `[`. Any LLM preamble
  containing a bracket (`[questions]`, footnote refs) makes `json.loads`
  fail → `None` → the whole 12-item batch silently falls back to
  deterministic categorisation.
- **Impact:** Silent loss of LLM categorisation for an entire batch; the
  "picked by the LLM" property degrades to deterministic without any signal.
- **Fix:** Iterate over every `[` position, returning the first that yields
  a valid balanced JSON array.
- **Confidence:** High
- **Found by:** Error Handling

## Suggestions

- **[B]** `_ask` returns a 2-tuple with no HTTP status — a non-200 wire
  response (401/403/422) records a silent empty-answer row indistinguishable
  from a real refusal. Return the status; record it; warn on non-200.
  (`representative_100.py:_ask`)
- **[C]** Categorisation cache `write_text` is non-atomic (truncate-then-write)
  — Ctrl-C mid-write or a concurrent run corrupts it. Use temp-file +
  `os.replace`. (`representative_100.py:categorize_pool`)
- **[E]** `_SEED` is stored in the sidecar but never seeds a PRNG; `random`
  is not imported. Selection is deterministic by sort key — remove `_SEED`
  and correct the docstring/payload to say "order-based deterministic".
- **[H]** `_scenario_to_question` is a third near-copy (also in `runner.py`
  and `unbiased_runner.py`). Extract to the lightweight `evals/bench/dataset.py`
  and import in all three.
