## Critical Issues

### [C1] tone_guard sentence splitter corrupts `e.g.` / `i.e.` / `etc.`
- **File:** `app/integrations/regenold/tone_guard.py:78`
- **Bug:** `_SENTENCE_SPLIT = re.compile(r"([.!?]+)(\s+|$)")` treats every period+space as a sentence terminator, including inside `e.g.` / `i.e.` / `etc.`. The post-split `_capitalise_first_letter` upper-cases the next word.
- **Repro:** `enforce_tone("Article 13 requires e.g. logs and FRIAs.")` → `"Article 13 requires e.g. Logs and FRIAs."`
- **Impact:** Ships on EVERY Stage-2 polish output containing common Latin abbreviations. Tone-judge regression vector (0.71 → 0.68 R55).
- **Suggested fix:** Replace `_SENTENCE_SPLIT.split(...)` with `app.engines.sentence_index.split_legal_sentences()` (the legal-aware splitter already handles `Art.` / `Annex N.` / `e.g.` / `i.e.` / `etc.`), OR add a negative lookbehind: `r"(?<!\be\.g)(?<!\bi\.e)(?<!\betc)[.!?]+"`.
- **Confidence:** High (95%, repro verified)
- **Found by:** Logic & Correctness specialist; Verifier confirmed

### [C2] R53.1-C / R54-Q1 scope anchors flip plainly off-topic queries in-scope
- **File:** `app/integrations/regenold/scope.py` lines 819-906 (R53.1-C `_AI_ACT_ANCHORS`), 1336-1372 (R53.1-C `KEYWORD_TO_ARTICLE`), plus R54-Q1 additions
- **Bug:** Substring-matching anchors `"individualised risk assessment"`, `"designating authority"`, `"high-risk"`, `"medical devices exemption"`, `"chapter v breach"`, `"training compute threshold"` are common English phrases used outside AI Act contexts.
- **Repro:** `classify_scope("designating authority over the kids")` → in_scope=True; `"I want to designate a notified body for my homemade jam fair"` → in_scope; `"Best high-risk hike in the Alps?"` → in_scope; `"individualised risk assessment for my mortgage"` → in_scope; `"medical devices exemption for my homemade cough syrup"` → in_scope.
- **Impact:** `zero_retrieval_fallback` ships spurious Art. floor instead of refusing; reopens R34 P0 false-positive class deliberately closed previously. Wasted Sonnet polish (5-15s per fired request). Possible DoS budget-burn vector for attackers on anon tier.
- **Suggested fix:** Require co-occurrence with an actual AI Act marker (`"ai"`, `"ai act"`, `"AI system"`) for these compound phrases, OR move them to `KEYWORD_TO_ARTICLE` only (doesn't widen scope gate). Narrow `"high-risk"` to `"high-risk ai"` (already exists; remove bare `"high-risk"`).
- **Confidence:** High (90%, repro verified; R34 OOS regression set STILL refuses — that bar held, but anchor surface is too broad).
- **Found by:** Logic & Correctness + Security specialists; Verifier confirmed

### [C3] `KB_VERSION` not bumped for R53.2 stub edits → engine cache + Neo4j seed stale
- **File:** `app/data/kb.py:16`
- **Bug:** `KB_VERSION = "2024.1689.v2"` is a static constant. R53.2 (commit `1748718`) edited `EC_CHECKER_OBLIGATION_MAP["Art. 25"]` (+9 lines: one-third fine-tune, small-mid-cap, Commission Guidelines) and `["Art. 101"]` (+5 lines: AI Office direct fining) but did NOT bump KB_VERSION.
- **Impact:** Two downstream invariants break:
  1. `app/routes/regenold.py:195 _engine_cache_key()` folds KB_VERSION into the sha256. Any process started on R52.1 code that cached an Art. 25 / Art. 101 question serves stale R52.1 prose until LRU eviction (512 entries) or restart.
  2. `app/main.py:439 _maybe_auto_seed_neo4j` SKIPS re-seeding when `current_kb == KB_VERSION`. Any previously-seeded Neo4j instance silently drifts from KB.
- **Suggested fix:** Bump `KB_VERSION = "2024.1689.v3"` in this fix PR. Add a CI lint that hashes `repr(EC_CHECKER_OBLIGATION_MAP)` and asserts the version string changes whenever the hash changes (snapshot file pattern).
- **Confidence:** High (95%, code paths confirmed by reading consumers)
- **Found by:** Concurrency & State specialist; Verifier confirmed

### [C4] ReDoS in widened compound-role regex (`_COMPOUND_PROVIDER_AND_DEPLOYER_RE`)
- **File:** `app/engines/scenario_classifier.py:212-224`
- **Bug:** Post-R54-B the pattern `(?:a|an|the)?\s*provider\s+and\s+(?:a|an|the)?\s*deployer` has nested optional alternations with adjacent `\s*` — classic backtracking shape. Measured timings: N=2000 → 36ms, N=4000 → 126ms, N=8000 → **590ms** on input `"both" + " "*N + "XXX"`.
- **Impact:** Anon-tier 30/min × 590ms = 18s wall time / minute per botnet IP. Partner-tier compounds. One adversarial request wedges a worker thread for ~0.6s.
- **Suggested fix:** Drop the optional `(?:a|an|the)?\s*` alternation (the prefix-whitespace makes the article truly optional), OR re-anchor with `\s+(?:a|an|the\s+)?` so article-prefix has mandatory leading whitespace, OR collapse adjacent whitespace tokens in `_normalise` before regex matching.
- **Confidence:** High (95%, timing measurements reproducible)
- **Found by:** Security specialist; Verifier confirmed

## Important Issues

### [I1] Compound-role STRONG phrases asymmetric to widened regex
- **File:** `app/engines/scenario_classifier.py:266-302` (STRONG_PHRASES) vs `212-224` (REGEX)
- **Bug:** R54-B regex matches `"both a deployer and a provider"` but `_COMPOUND_STRONG_PHRASES` only carries provider-first variants. Result: regex flags compound_roles, helper flags weak → 8-ref budget instead of 12 for the very V2 `role_ambiguity` paraphrase shape R53.1-B was designed to lift.
- **Suggested fix:** Add 5 mirror phrases: `"both a deployer and a provider"`, `"both deployer and provider"`, `"both the deployer and the provider"`, `"as both a deployer and a provider"`, `"as both deployer and provider"`. Plus 3 mirror importer/distributor variants.
- **Confidence:** High (85%, repro verified)
- **Found by:** Contract & Integration specialist; Verifier confirmed

### [I2] Widened `_COMPOUND_PROVIDER_AND_DEPLOYER_RE` over-fires on definitional QA
- **File:** `app/engines/scenario_classifier.py:212-224`, with `_DEFINITIONAL_QA_SHAPE_RE` gate at line ~360-370
- **Bug:** Post-R54-B regex matches bare `"a provider and a deployer"`. `_DEFINITIONAL_QA_SHAPE_RE` doesn't match `"What's the difference between..."` (apostrophe-s contraction) so Gate 1 doesn't fire; `_THIRD_PERSON_ENTITY_RE` matches `"A provider"` so Gate 2 passes. Net: definitional QA fires compound-role → 8-ref budget (above QA's 5).
- **Repro:** `_detect_compound_roles("What's the difference between a provider and a deployer?")` → `['provider', 'deployer']`
- **Impact:** davidath QA Strict F1 drift on definitional rows; this is one cause of the bench parity Ans Strict dropping 0.3066 → 0.3063 last round (within noise but trending down).
- **Suggested fix:** Add `"what'?s\s+the\s+difference"` to `_DEFINITIONAL_QA_SHAPE_RE` AND/OR tighten the widened regex to require a `\bboth\b` qualifier on the article-less variants.
- **Confidence:** High (80%)
- **Found by:** Logic & Correctness + Contract + Security specialists; Verifier confirmed

- **Found by:** Error Handling specialist; Verifier confirmed

### [I4] Empty-sentence rewrite produces orphan-period artefacts
- **File:** `app/integrations/regenold/tone_guard.py:107-128`
- **Bug:** When `_rewrite_first_person_mid_sentence` strips an entire sentence to empty (e.g., `"In our view."` or `"We should also."`), the rebuild loop appends `""` + `"."` + `" "` + next sentence → produces `". Article 13 applies."` with a leading orphan period.
- **Repro:** `enforce_tone("In our view. Article 13 requires logs.")` → `". Article 13 requires logs."`
- **Impact:** Ships malformed prose to wire when Stage-2 polish produces a single-purpose first-person sentence.
- **Suggested fix:** After rewriting, if `cleaned == ""`, skip appending the punctuation+gap for this sentence (drop it entirely).
- **Confidence:** Medium-High (75%, repro verified)
- **Found by:** Error Handling + Contract specialists; Verifier confirmed

### [I5] Bare `except Exception: pass` on `classify_scenario_query` has zero telemetry
- **File:** `app/routes/regenold.py:1748-1758`
- **Bug:** No log, no `_trace_*` recorder. Any systematic crash in `classify_scenario_query` silently downgrades ALL questions to 5-ref QA budget with no audit trail.
- **Suggested fix:** `logger.warning("scenario_budget_calc_failed", exc_info=True)` + `_trace_note("scenario_classify_error", str(exc))` so post-mortem judges see the failure mode.
- **Confidence:** High (80%)
- **Found by:** Error Handling specialist; Verifier confirmed
