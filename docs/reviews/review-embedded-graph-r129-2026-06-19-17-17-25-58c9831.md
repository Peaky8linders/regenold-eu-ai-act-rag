## Executive Summary

The embedded backend's *internal* implementation is solid (fail-soft, import-time
self-check, correct recursive-CTE traversal, bound-param SQL — no injection,
bounded recursion). The risk clustered at the **boundary the go-live exposed**: the
new backend was activated *before* its observability. Four agents independently
converged on the #1 finding — `/healthz/graph` and the boot log are Neo4j-only and
now **misreport the healthy live embedded graph as disabled/broken**, which would
false-page on-call and mask a real embedded-build failure. Highest individual-finding
confidence: 95 (Contract). No security vulnerability (SQL injection, SSRF, secret
leakage all verified clean; recursion provably bounded). **10 fixes shipped**, 4
items deferred with rationale.

## Critical / High — FIXED

### [C1] `/healthz/graph` + boot log misreport the live embedded graph as disabled
- **Files:** `app/main.py` (`healthz_graph` ~814; startup graph log ~116)
- **Found by:** Contract (conf 95), Error-Handling (conf 85), Eng-manager (P0-1/P0-2), Logic (implicit)
- **Bug:** both surfaces are gated on `NEO4J_URI` and probe only the Neo4j client.
  Under `REGENOLD_GRAPH_BACKEND=embedded`, `client._should_activate` returns False,
  so `/healthz/graph` returns `graph_enabled=false` + `"graph_disabled: ... neo4j
  driver is not installed"` (if `NEO4J_URI` lingers) or `"NEO4J_URI not set"` (if
  cleared), and the boot log emits `"graph client did not activate"` — all while the
  embedded graph is healthy and serving 2-hop. The embedded graph's health/node-count
  was observable **nowhere**.
- **Impact:** an uptime monitor alerting on `graph_ok=false` (the documented contract)
  false-pages on a working system; a real embedded-build failure (caught + swallowed
  to `enabled=False`) is invisible. Single most likely cause of a 3am false page.
- **Fix:** added an embedded-backend branch (before the `NEO4J_URI` check) to both
  `healthz_graph` (reports `backend=embedded`, `graph_enabled`, `node_counts`,
  `edge_counts`, `detail="ok (embedded)"`) and the boot startup log
  (`graph_backend=embedded enabled=… node_count=… edge_count=…`). Added a `backend`
  field to the health payload so on-call always sees which engine answered.
- **Confidence:** High

### [C2] `REGENOLD_STAGE2_SIMPLE_SKIP` + `REGENOLD_GRAPH_BACKEND` + `REGENOLD_MAX_HOP2` missing from the engine cache key
- **File:** `app/routes/regenold.py::_engine_cache_key`
- **Found by:** Error-Handling (conf 90 / 72), Contract (conf 80)
- **Bug:** R129 added `_stage2_simple_skip_enabled()` (flips `GraphRAGResponse.answer`
  + `stage2_landed`) and activated the backend selector (picks embedded vs Neo4j
  2-hop → can return different `references`). Neither, nor `REGENOLD_MAX_HOP2` (sizes
  the 2-hop budget), was in the cache key — a direct violation of the project's own
  R30/R56/R79 cache-poisoning doctrine ("any input that flips engine behaviour must
  be in the key"), which the same R129 commit applied to `REGENOLD_FUSION_JUDGE`.
- **Impact:** a mid-deploy flip of any of these serves stale cached answers/references
  for previously-asked questions until LRU eviction.
- **Fix:** appended all three to the `engine_flags` tuple with the doctrine comment.
  Default/bench env leaves them unset/neo4j → davidath byte-identical.
- **Confidence:** High

### [C3] No end-to-end test exercises the now-live embedded path
- **File:** `tests/conftest.py:118` pins `REGENOLD_GRAPH_BACKEND=neo4j` for the whole suite
- **Found by:** Contract (conf 85), Logic (conf 72), Eng-manager (P1-1)
- **Bug:** the suite runs against the **Neo4j** selector; the embedded path was only
  unit-tested (`test_embedded_graph.py` calls `expand_2hop` directly). The production
  wiring — route/`kb_search.top_articles_by_relevance` → `expand_2hop` →
  `_embedded_rows` → `two_hop` → `fuse_with_kb_xrefs` under the embedded backend — had
  **zero** coverage. "Green suite" gave false confidence in the live config.
- **Fix:** new `tests/test_r129_embedded_review.py` (11 tests): embedded
  `/healthz/graph` branch, `is_enabled()` true-without-Neo4j, end-to-end
  `expand_2hop`+`fuse` through the embedded graph, close()/read race-safety, the 3
  new cache-key flags, and the fusion tie-break stability.
- **Confidence:** High

### [I1] `EmbeddedGraph.close()` races with in-flight reads (latent crash)
- **File:** `app/graph/embedded_graph.py`
- **Found by:** Concurrency (conf 80)
- **Bug:** every read held `self._lock`, but `close()` did not, and the read methods
  re-read `self._conn` inside the lock after an unlocked `is None` guard. A `close()`
  (nulls `self._conn` + closes the SQLite handle) interleaving between the guard and
  the `execute` → `AttributeError` / `Cannot operate on a closed database`. Today only
  `_reset_embedded_graph_for_tests()` calls `close()`, but the introspection methods
  are now on the **request path** (the new `/healthz/graph` branch).
- **Fix:** `close()` now acquires `self._lock`; every read binds `conn = self._conn`
  **inside** the lock and null-checks the local, so a concurrent close can't change
  the object mid-statement. Verified with a 4-reader-vs-close concurrency test.
- **Confidence:** High

### [I2] `kb_search` `expansion = []` is a wrong-type sentinel (only accidentally safe)
- **File:** `app/data/kb_search.py` (~937)
- **Found by:** Error-Handling (conf 80)
- **Bug:** the success path returns a `GraphExpansion` dataclass (always truthy — no
  `__bool__`/`__len__`); the `except` set `expansion = []`; the guard `if expansion`
  therefore tests "was a GraphExpansion produced", not emptiness. Safe only because the
  sentinel was hardcoded `[]` and never reached `fuse_with_kb_xrefs` (which reads
  `.hop2_articles`). Any future tweak (non-empty list sentinel, or `if
  expansion.hop2_articles`) would hit `AttributeError` on a `list`, on the retrieval
  hot path.
- **Fix:** sentinel → `GraphExpansion()` (type-correct), guard → `if
  expansion.hop2_articles` (real emptiness test). Behaviour-identical, type-correct.
- **Confidence:** High

### [I3] "Deterministic" fusion judge tie-break is order-dependent
- **File:** `app/engines/fusion.py::_deterministic_judge`
- **Found by:** Concurrency (conf 72)
- **Bug:** `drafts` is appended in `as_completed` (wall-clock) order; a score TIE
  resolves to whichever serverless panel member returned first. So the judge labelled
  "deterministic" returns different answers for byte-identical inputs — and the route
  engine-cache assumes identical inputs → identical output.
- **Fix:** iterate `sorted(drafts, key=lambda d: d[0])` so ties break on a stable
  (label) key. Pinned by a both-orderings test.
- **Confidence:** Medium-High

## Deferred (documented — not fixed this pass)

- **[F1] 2-hop budget exhausted by hop1 for hub seeds (Logic, conf 88).** `expand_2hop`
  orders `(hops, num)` then `LIMIT cap` (`cap = max(max_hop2*2, 4)` = 10 by default),
  so hop1 rows fill the LIMIT before any hop2 row for any seed whose 1-hop degree ≥ 10
  — the 2-hop feature silently contributes **nothing** for hub seeds. This is
  **pre-existing in the Neo4j path too** (shared `LIMIT` design) and is now live via
  embedded. **Deferred because fixing it changes live retrieval output (more hop2 refs
  → over-citation risk) in a way the davidath bench cannot measure (2-hop is OFF in
  the bench).** Per project discipline it needs a gated fix + live representative-100 +
  judge A/B, not a blind change to the competition endpoint. The fix shape: exclude
  hop1/direct neighbours *inside* the query before the LIMIT (so the cap counts only
  hop2-only candidates), gated + A/B'd.
- **[Security] `/healthz/graph` unauthenticated + un-rate-limited (conf 70 / 62).**
  Pre-existing; intentionally public for uptime monitors (matches `/healthz/llm`). The
  Neo4j-query-amplification vector is moot under the embedded backend (no Neo4j queries
  fire). Discloses only version/kb_version (common for health endpoints). Changing
  health-endpoint auth is a product decision out of this round's scope.
- **[Logic F4/F5] `external_embeddings` lost chat-wrapper guard / dead `_targets_chat_wrapper`.**
  R129 latency change, tangential to the graph go-live. Only bites an operator who
  explicitly sets `REGENOLD_EXTERNAL_EMBEDDINGS=1` while `OPENAI_API_BASE` is the chat
  wrapper (a misconfiguration). Low priority; left for a follow-up.
- **[Logic F3] R129 simple-skip `record_note` unreachable when reasoning is active.**
  The skip is coupled to `force_stage2` (set whenever a trace is active), so
  `?include_reasoning=true` both forces Stage-2 *and* makes the skip's telemetry a
  no-op. The gate is default-OFF; the trace coupling is a known `?include_reasoning`
  trap. Documented; not load-bearing.

## Why these fixes hold the davidath line

Every shipped change is inert on the deterministic davidath bench by construction:
the bench leaves `REGENOLD_GRAPH_2HOP` unset (2-hop OFF regardless of backend), runs
`provider=cli` (fusion + Stage-2 OFF), and never hits `/healthz/graph` or the boot
log on the `/ask` path; the cache-key additions are constant segments in the bench env
(answers unchanged; ~0% in-run cache hit). The wins land **live** — the embedded graph
becomes observable, the cache can't serve stale answers across an env flip, the close
race and the fusion non-determinism are closed, and the now-live path finally has
end-to-end test coverage.
