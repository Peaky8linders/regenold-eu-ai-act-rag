## Executive Summary

The bundle has three genuinely good pieces (the ISO/MDR **Stage-2 bridging** — correctly non-citable; the **clinical-trial disambiguation** — R109-aligned; the device-class **classifier** intent) but **must not ship as authored**. All three review lenses independently returned **REQUEST CHANGES**. Highest-severity issues: (C1) the 7 ontology-hop-map additions fire on generic **provider/GPAI** QA (not just MedTech) and, via the R112 ref-budget bump, re-open the R77-I6 over-citation regression — **measured davidath QA Ref Strict −0.012 / Ref Conciseness −0.015, Ref Loose flat (zero recall gain)**; (C2) bare activity markers (`x-ray`, `diagnostic imaging`, `patient vital`, `robotic surgery`) **confidently-wrong-classify** scheduling/admin/educational tools as high-risk (hard rule #4 — an "x-ray appointment scheduler" is not a medical device); (C3) the whole bundle is **not env-gated**, so it cannot be A/B'd or rolled back (hard rule #6 — ab_judge is the merge gate, not davidath). All fixed on this branch.

## Critical Issues

### [C1] Ontology-hop-map additions over-cite generic provider/GPAI QA
- **File:** `app/routes/regenold.py:319-332` (added keys) → consumer `_apply_ontology_hops:353` → budget bump `:5647`
- **Bug:** 7 new keys (Article 6/6.1/25/43/51/53, Annex I) ride the pre-existing `wh + provider/deployer` and `requirements` triggers, so they inject on non-MedTech QA. The GPAI hops (Article 51→53/55, 53→Annex XI/XII) are not MedTech at all. Because injection trips the R112 `_effective_max_refs` bump (3→7), extra pre-existing candidates also surface.
- **Impact:** davidath QA — **18/137 rows over-cite**; Ref Strict 0.5543→0.5421, Ref Conciseness 0.4395→0.4241, Ref Loose flat. R251/R142.1 over-citation antipattern.
- **Fix:** removed all 7 from the general map; added a 3-key `_MEDTECH_HOP_MAP` (Article 6 / Annex I / Article 43 → the Annex-I conformity pathway) applied **only** when `is_medical`, behind `REGENOLD_MEDTECH_HOP` **default OFF** (ab_judge-measurable). GPAI hops dropped entirely.
- **Confidence:** High. **Found by:** doctrine/rubric + lead measurement.

### [C2] Over-broad device markers → confidently-wrong high-risk (hard rule #4)
- **File:** `app/engines/scenario_classifier.py:936-946` (`_medtech_markers`) + `:726-735` (`_HIGH_RISK_MARKERS` device block)
- **Bug:** bare `x-ray`, `diagnostic imaging`, `patient vital`, `robotic surgery` force `high-risk-annex-i` with no device-status condition. Repro: *"Our software helps radiologists schedule x-ray appointments"* → high-risk. Under Art 6(1)+Annex I a medical-device AI is high-risk only where it **is / is a safety component of** a device requiring **third-party conformity assessment**.
- **Fix:** new `_MEDTECH_DEVICE_MARKERS` = device-STATUS phrasings only (class II/IIa/IIb/III, IVDR B/C/D, SaMD, "software as a medical device", "safety component of a medical device", "surgical robot"). Dropped the four bare activity/modality nouns. Deduplicated the two divergent tuples into one source; removed the shadowed device block from `_HIGH_RISK_MARKERS`.
- **Confidence:** High. **Found by:** all 3 lenses + lead repro.

### [C3] Bundle not env-gated → un-A/B-able / no rollback (hard rule #6)
- **File:** classifier + bridging + ontology change — no env flag.
- **Fix:** master gate `REGENOLD_MEDTECH` (default ON) over the classifier tier + Stage-2 bridging; `REGENOLD_MEDTECH_HOP` (default OFF) over the hop. Both folded into `_engine_cache_key` (R30/R56/R79 cache-poisoning doctrine). `REGENOLD_MEDTECH=0` reproduces the pre-R263 baseline for a clean ab_judge OFF↔ON A/B.
- **Confidence:** High. **Found by:** doctrine + eng-manager.
