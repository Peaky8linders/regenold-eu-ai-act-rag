**Date:** 2026-08-22 | **Commit:** 1cab8f0 | **Scope:** 26 files, +3014 / -77

## Verdict

**BLOCK — do not scrap, but do not ship as-is.**

The diagnosis behind this PR is good and the foundation is sound. Hoisting the Bedrock
leg out of the `response.error` branch (`app/engines/_graph_rag_impl.py:900-960`) is a
real fix to a genuinely dead fallback; runtime counters are the right instrument for a
repo whose recorded failure mode is "a routing lever that reads plausibly in the diff and
makes zero calls" (R329/R331); and `tests/test_r360_stage2_transport_policy.py` is
two-sided — it proves that with `REGENOLD_STAGE2_STRICT_TRANSPORT=0` the Groq hatch is
still reachable, so the sealing tests mean something. 99 tests for a routing change is the
right ratio.

But **the PR's headline claim — "no request goes any other way" — is false at HEAD**, and
the live production counters gathered for this review are the evidence: two requests, both
legs at zero successes, a green `llm_ok`, `refused_by_provider {"groq": 2}`, and a wrapper
dial *inside* the Bedrock leg that nothing counted.

Block on **A1** (a boot path that seeds over a live graph), **B1** (the fallback leg
re-enters the primary, bypassing the destination pin the PR was written for), **B5** (the
health probe reports green from credentials while its own counters in the same JSON body
say both legs are failing), and **B2** (no breaker: every request in the current outage
pays the full leg-1 budget before degrading).

Then split per **C16**, collapse the counter recording behind one `try/finally` helper
(**C3**, **B9**), reconcile `AGENTS.md` (**C8**), and add the diagram (**C8**).

Counts: **P0 1 · P1 10 · P2 16 · P3 3.** No finding fell below confidence 8, so the
suppression appendix is empty — stated explicitly rather than omitted.

## Step 0 — Scope challenge

### What already solved this, and where did the policy naturally belong?

Three existing homes were available; the PR used none, and one of them is now actively
fighting it.

* `app/engines/_graph_rag_impl.py:205` — `_graph_rag_provider()` is the repo's existing
  per-call provider resolver. `resolve_stage2_provider()` is a Stage-2-specific twin,
  injected at two call sites (`:1298`, `:8744`) that already had the raw
  `os.getenv("P2P_GRAPH_RAG_PROVIDER")` read. A one-line change inside
  `_graph_rag_provider` was available.
* `app/llm/openai_wrapper_provider.py:403-405` already owns base-URL resolution. R360.7's
  host pin re-derives that value from the outside via a four-way guess
  (`_graph_rag_impl.py:978-992`) with a `MagicMock` workaround baked into it. Pinning
  belongs in the constructor, where there is exactly one value and no guessing — and
  where it would also cover `bedrock_client.py:1036`, which the guard currently misses.
* `app/llm/bedrock_client.py:991-1067` **already implements a cross-provider fallback with
  an enable flag and a served-by audit log** — the mirror image of what `stage2_policy`
  builds. The PR neither reuses its idiom nor notices it. That omission is finding **B1**.

The genuinely new and justified part is the counters. The refusal machinery largely
reimplements `if is_*_provider_enabled()` guards that already existed at each site.

### Complexity check — is 26 files proportionate?

**No.** The transport contract is ~8 files. This is three PRs stapled together: a transport
contract, an Annex III(1)(b) legal-fidelity KB fix, and an eval/infra hygiene sweep. Each
has a different blast radius and a different verification instrument (counters / grounded
judge / boot log). Bundling them means a revert of one is a revert of all three.

### Search check — right shape?

**[Layer 3] first-principles where [Layer 1] was available and better**, in two places:

* **Base-URL pinning.** `httpx.Client` is constructed with `base_url=` at
  `openai_wrapper_provider.py:437`. The tried-and-true idiom is to validate at
  construction (or via an `httpx` request event hook) so *every* call through that client
  is pinned. Hand-rolling a `urlsplit` allowlist at one call site is strictly weaker.
* **Breaker.** This repo already ships the pattern twice — `app/graph/timeouts.py:169-172`
  (`GRAPH_BREAKER_THRESHOLD = 3`, `GRAPH_BREAKER_COOLDOWN_S = 60.0`, half-open probe at
  `:187-203`) and `app/llm/intent_classifier.py:353`. The Stage-2 chain is the most
  expensive transport in the system and the only hot path without one. That is ~15 lines of
  reuse, not new machinery. See **B2**.

Correct and boring, and worth crediting: process-global counters, and choosing a
two-element chain over a general policy engine.

### Completeness

It stopped short at exactly the boundary between "the id says X" and "the packet went to
X": **B1** (leg 2 re-enters leg 1, unpinned and uncounted), **B5** (health reports from
credentials, never from a dial), and the counter asymmetry (**B9**, **C3**) which makes
`transport_stats()` unreconcilable — the one thing the module docstring promises it is for.

**There is none.** The de-facto register is `docs/ROUNDS.md` ("Closed Directions",

the unused `execute_read_strict` call site — have no home. **Recommend adding
`.planning/DEFERRED.md` and seeding it from this review.**

### A1 — [P0] (confidence 10/10) `app/main.py:606` — the auto-seed guard reads a swallowed Neo4j failure as "graph is empty" and seeds over live Aura

`GraphClient.execute_read` **never raises** — it swallows and returns `[]`
(`app/graph/client.py:207-208`). So a Neo4j read failure on the new count query yields
`_count_rows = []` → `[{}]` → `.get("c") or 0` → `_node_count = 0` → falls past the
`if _node_count > 0` guard → `reason = "graph_empty"` → **seeds over a live graph**. That
is verbatim the failure R360.6 says it fixes.

```python
# app/main.py:606-609
                _count_rows = client.execute_read(
                    "MATCH (n) RETURN count(n) AS c"
                )
                _node_count = int((_count_rows or [{}])[0].get("c") or 0)

# app/graph/client.py:207-208
        logger.warning("Neo4j execute_read exhausted retries: %s", last_exc)
        return []
```

The covering test takes the wrong branch: `tests/test_r360_6_auto_seed_guards.py:98`
(`test_an_unreadable_node_count_is_not_seeded`) uses a double whose `_read` **raises**.
Production returns `[]`. The PR's own sibling file asserts the real contract one screen
over — `tests/test_r360_12_verified_bug_fixes.py:100` asserts
`client.execute_read(...) == []` under a raising `_run_read`. Two test files in one PR
encode contradictory models of the same method, and the seeder test picked the wrong one.

Reproduced against the real `_maybe_auto_seed_neo4j`: a client whose `execute_read`
returns `[]` for every query yields seed reasons `['graph_empty']`.

**Fix.** Switch `app/main.py:606` to `client.execute_read_strict(...)` — which this PR
added and which has **zero non-test call sites in `app/` outside `kg_context`'s `getattr`
probe** — and add `test_a_swallowed_count_failure_is_not_seeded` whose double *returns*
`[]`. Keep both tests so either client contract is pinned.

**Trade-off.** Not doing it leaves a boot-time write over live production graph data one
Neo4j transient away, guarded only by `NEO4J_AUTO_SEED` defaulting to `0` — i.e. by a flag,
not by the guard the PR added. `AGENTS.md` makes protecting live Aura nodes a hard rule.

### B2 — [P1] (confidence 9/10) `app/llm/stage2_policy.py:74` — no circuit breaker: a known-dead primary is re-dialled at full timeout on every request

`stage2_policy` collects exactly the state a breaker needs (`primary_attempts`,
`primary_failed`) under a lock and never reads it back. `grep -n "monotonic|circuit|
cooldown|breaker|trip" app/llm/stage2_policy.py` returns **zero matches** — no open /
half-open state, no failure window, no cooldown.

In the state production is in — `primary_attempts 2 / primary_ok 0 / primary_failed 2` —
request #3 dials the same dead tunnel again and pays the same full budget:

```python
# app/llm/openai_wrapper_provider.py:426-429
        self._timeout = (
            timeout if timeout is not None
            else float(os.getenv("OPENAI_TIMEOUT_SECONDS", "60"))
        )
# app/llm/openai_wrapper_provider.py:238
_CONNECT_TIMEOUT_SECONDS = 5.0
```

then boto's three attempts on leg 2 (`bedrock_client.py:282`,
`retries={"max_attempts": 3, "mode": "standard"}`), then B1's second wrapper dial. The
measured 23.8 s is not an outlier to amortise; it is the steady state, per request,
forever.

This is a *reuse* failure, not a missing feature. `app/graph/timeouts.py:169-172` ships the
pattern with `GRAPH_BREAKER_THRESHOLD = 3` / `GRAPH_BREAKER_COOLDOWN_S = 60.0` and a
half-open probe at `:187-203`, and its docstring argues the case in exactly these terms.

Underneath is the architecture question, and it deserves a plain answer: the primary
transport is one operator's laptop, running one wrapper process, behind one cloudflared
tunnel, on one Claude Max OAuth token that currently has **no refresh token** and whose
`/v1/auth/status` is a known liar. There is no redundancy at any link. For a competition
submission this is not an acceptable production architecture.

**Fix (this PR).** Add `_primary_tripped_until: float` next to `_STATS` under the same
lock; on N consecutive leg-1 failures set `monotonic() + 60`, and have the leg-1 call site
at `_graph_rag_impl.py:1006-1015` skip straight to `_try_bedrock_fallback` while tripped,
with one probe per cooldown. Expose `primary_circuit_open` in `transport_stats()`. Add a
test asserting the 4th call after 3 failures makes **zero** `provider.complete` calls.

**Fix (separate PR, operator decision).** Either restore a refresh-capable credential with
an expiry probe that alerts *before* expiry, or accept Bedrock as primary and the tunnel as
an optimisation. See Decision 2.

**Trade-off.** Not doing the cooldown: during any tunnel outage every user request stalls
for the better part of a minute before producing a deterministic answer, turning a quality
degradation into a latency outage on a scored axis. With `--workers 2` and a bounded anyio
threadpool, a sustained outage becomes a saturation event while `/healthz` returns 200.

### B3 — [P1] (confidence 9/10) `app/llm/bedrock_client.py:1171` — no end-to-end deadline across the two legs

The wrapper provider carries a proper wall-clock deadline *inside itself*
(`openai_wrapper_provider.py:533`, `deadline = start + budget_seconds`, and it correctly
skips a 429 retry that would overrun). That deadline is never threaded across the chain, so
composed cost is the sum of every leg's independent budget.

```python
# app/llm/bedrock_client.py:1171-1172
for idx, model_id in enumerate(live):
    resp = provider.complete(replace(req, model=model_id))

# app/llm/bedrock_client.py:259-260, 280-282
_DEFAULT_CONNECT_TIMEOUT = 5.0
_DEFAULT_READ_TIMEOUT = float(os.getenv("BEDROCK_TIMEOUT_SECONDS", "60"))
            connect_timeout=_DEFAULT_CONNECT_TIMEOUT,
            retries={"max_attempts": 3, "mode": "standard"},
```

Worst case for one Stage-2 request: leg 1 up to 65 s + one 429 retry; then
`complete_with_fallback` walks every model in `fallback_chain_for(primary)` not
entitlement-cached, each at `read_timeout=60` × `max_attempts=3`; then B1 dials the tunnel
a second time at another full 60 s. The `_DENIED_TTL_SECONDS = 900.0` cache covers only
*entitlement* (403) errors, so a network- or timeout-class Bedrock failure is re-walked in
full next request.

Verified: `deadline|asyncio.wait_for|LATENCY_BUDGET` has **zero hits** in
`app/routes/regenold.py`. There is no request-level cap anywhere between the route and the
sockets.

**Fix.** Add `stage2_deadline()` to `stage2_policy` (env `REGENOLD_STAGE2_TOTAL_BUDGET_S`,
default ~75 s), set once at the top of `_openai_wrapper_complete_for_graph_rag`, and pass
`timeout_seconds=max(1.0, deadline - now)` into both `OpenAIWrapperRequest` and
`BedrockRequest`; have `_try_bedrock_fallback` return `None` immediately below a floor.
Same shape `openai_wrapper_provider.complete` already implements, hoisted one level.

**Trade-off.** Without it you cannot state a latency SLO for the failure path, which makes
an error budget unwritable — and a slow-failure mode (throttled Bedrock region, saturated
Max subscription) occupies a worker for minutes per request.

### B4 — [P1] (confidence 9/10) `app/routes/regenold.py:345` — cross-family failover to Qwen 3 is invisible on the wire, and the Qwen answer is then **cached**

The design admits the concern and does not act on it. `stage2_fallback_model()`'s docstring
states plainly that "the fallback for a *Claude Opus* primary is then a different model
family, and an answer served from leg 2 is not the answer any A/B measured." But there is
no signal that leg 2 served.

```python
# app/routes/regenold.py:344-346
        stats = getattr(rag_res, "graph_stats", None) or {}
        if stats.get("stage2_call_failed"):
            return _FALLBACK_WARNING_TEXT
```

`context.stage2_call_failed = True` is set only at `_graph_rag_impl.py:9335`, on the
*both-legs-exhausted → deterministic* path. When Bedrock **succeeds**, Stage-2 did not
fail, `warning` stays `None`, `response_model_exclude_none=True` strips it, and the JSON is
byte-identical to a healthy Claude Opus response. The only trace is
`record_note("bedrock_auto_fallback_success")`, and `record_note` is a no-op without an
active trace — i.e. on every request that is not `?include_reasoning=true`. Provenance is
**unrecoverable after the fact**.

Worse (from the outside voice, verified): the cache does not distinguish the legs either.

```python
# app/routes/regenold.py:6857-6861
        _cacheable = (
            not _stats.get("stage2_call_failed")
            and rag_res.confidence >= _MIN_CACHEABLE_CONFIDENCE
            and _stats.get("nodes_traversed", 0) > 0
        )
```

A *successful* Qwen leg-2 answer is cacheable and is then served to later requests on a
healthy tunnel. `_engine_cache_key` folds in `strict` and the **configured** fallback model
name, which defaults to `""` — so the Qwen-vs-Opus distinction the module's own docstring
calls answer-flipping contributes zero bits. One degraded window poisons the cache with a
different model family's prose. (Currently masked only because `nodes_traversed > 0` fails
with Aura down — you are protected by a second outage.)

**Fix.** Set `context.stage2_served_by = "bedrock"`, surface it in the telemetry block
alongside `retrieval_path`, add it to `_cacheable`/`_engine_cache_key`, and add a second,
distinct warning string for cross-family service kept separate from `_FALLBACK_WARNING_TEXT`.
If a new wire field is unacceptable for the competition response shape, telemetry +
INFO-level log with the request id is the floor. Update the `RegenoldAskResponse` docstring,
which currently teaches consumers the now-false invariant that `warning`'s presence is the
degraded-mode signal. See Decision 4.

**Trade-off.** Every quality measurement taken through the live endpoint silently mixes two
model families with no way to partition the rows afterward — the exact trap `CLAUDE.md`'s
R330 section documents for `.env` coupling, reproduced at the model layer. For a legal-answer
product, unauditable authorship is a governance problem, not just an engineering one.

same object `fallback_attempts 2 / fallback_ok 0 / fallback_failed 2`.

And `tests/test_r360_stage2_transport_policy.py:932` locks it in with fake AWS keys and
zero Bedrock dials:

The test's own docstring states the goal — a monitor must tell "degraded but serving" from

Related and unaddressed: health and dispatch use **two different resolvers**.
`healthz_llm` computes `provider_label = resolve_provider(...)` (`app/main.py:1052`) while

**Trade-off.** `llm_ok` goes green on the presence of an AWS key rather than on the service
answering — the exact failure the endpoint exists to catch. A 3am operator reads "bedrock
fallback active", goes looking at the tunnel, and every user gets deterministic answers. And
the next person to fix it has to argue with a green test first.

## 4. Performance

Direct answers to the questions asked, then the findings (which live above as **B2**, **B3**,
**C9**, **C10**, **C11**, and the leg-2 cost half of **B9**).

1. **Circuit breaker on the Stage-2 chain? NO.** See **B2**. The measured 23.8 s is paid in
   full on every request, forever; there is no state that remembers the previous 100 failures.
2. **Backoff? NO.** A dead primary is re-dialled at full request rate. The only backoff in the
   path is the 429 `Retry-After` sleep, which does not apply to a 500/401.
3. **`_STATS_LOCK` contention — negligible, and worth saying plainly.** Four to six
   acquisitions per request, each guarding a single `dict[str] += 1`; no I/O, no logging, no
   imports inside any critical section (`refuse()` correctly does its `logger.warning` and
   `record_note` *after* releasing). `transport_stats()` copies an 8-key dict. Low microseconds
   against a request that spends 20-60 s in Stage-2. **Not a finding. Leave it alone.**
4. **Is `/healthz/llm` polled by Railway? NO — verified.** `railway.toml:3` is
   `healthcheckPath = "/healthz"`. The platform never fires the billable probe. (`/healthz`
   itself has an opt-in Groq probe at `main.py:941`, but `_healthz_probe_enabled()` defaults to
   `"0"` and it is capped at 16 tokens / 5 s — latent, not live. Worth noting only because R360
   bans Groq from Stage-2 while leaving a Groq call on the platform-polled endpoint.) The real
   cost is **C9**.
5. **Neo4j per-request cost with Aura NXDOMAIN.** The graph layer *does* have a proper breaker
   (`app/graph/timeouts.py:169-172`, threshold 3, cooldown 60 s) — and this PR is what finally
   turned it on, by accident (**C10**). Net: dead-Aura cost drops from ~750 ms × every read ×
   forever to ~2.25 s once per 60 s per worker. The residual is worker-side (**C11**).

## Cross-model tension

Six places where the fallback outside voice and the section findings genuinely disagree, or
where the outside voice raised something the sections did not. Both positions are stated
neutrally, with what would settle it.

### T1 — Is the policy module the right primitive at all, or should the off-contract providers just be deleted?

**Sections:** the module is a sound foundation; fix the four blockers and it ships. Runtime
refusal plus counters is the instrument that proves the lever fires, which is this repo's
recorded failure mode.

**Outside voice:** 299 lines of policy plus a 1040-line test file express "call the wrapper;
if that fails call Bedrock". Everything being refused — Groq, Gemini, the Mistral/Groq fusion
members, the `anthropic`/`gemini` branches — is code in *this* repo under *your* control.
`git rm` is unfalsifiable by construction: no flag, no counters, no cache-key bit, no test
file. The R331 "prove it fires" argument applies to *adding* behaviour, where a call site can
silently not fire; it does not transfer to *removing* providers.

**What would change the answer:** whether the OFF arm is genuinely supported. If
`REGENOLD_STAGE2_STRICT_TRANSPORT=0` is a real operational escape the operator expects to use
(and the four re-pinned legacy suites suggest someone thinks it is), the module earns its
keep and **C15** must be fixed. If strict-ON is the contract and OFF exists only as a panic
button nobody will reach for, then the flag, the refusal machinery and half the test file are
ceremony, and deletion is smaller and safer. **This is Decision 5.**

### T2 — Is the shipped, measured effect of this commit *negative* on Answer Correctness?

**Sections:** the transport contract is directionally right; the problem is the four blockers.

**Outside voice:** read `refused_by_provider {"groq": 2}` carefully — Groq was **reached**,
meaning it would have answered. Pre-R360 those two users got a Groq answer; post-R360 they get
a deterministic non-LLM answer. On the competition's Answer Correctness axis the shipped effect
of this commit, right now, is negative. The Groq objection in the docstring is real (compressed
system prompt, unmeasured by any eval) but it argues for fixing or deleting the Groq path, not
for refusing it while both replacements are down.

**Neither side verified this with a judge run**, and it is testable: a pairwise `ab_judge` of
`STRICT_TRANSPORT=1` vs `=0` under the *current* degraded conditions would settle whether a
Groq answer beats a deterministic Stage-1 answer on this corpus. Note the repo's own memory
records deterministic Stage-1 as surprisingly strong on Ref axes and weak on Answer axes, which
cuts toward the outside voice. **This is Decision 6.**

### T3 — Should there be a third state (`bedrock-primary`) rather than one strict bit?

**Sections:** did not raise it. The architecture finding treats strict-ON plus the Bedrock leg
as the intended shape.

**Outside voice:** `resolve_stage2_provider` deliberately collapses
`P2P_GRAPH_RAG_PROVIDER=bedrock` to the tunnel, calling Bedrock-as-primary "an inversion of the
operator contract". But the tunnel is *structurally* dead — expired OAuth, no refresh token —
which is not a hiccup a fallback is for. The operator's natural recovery ("pin Bedrock
directly") is now forbidden by code, and the only remaining lever re-arms Groq, Gemini, Mistral
and the fusion panel simultaneously. One bit is controlling two orthogonal decisions: *which
providers are permitted* and *whether leg 1 is skippable*.

**What would change the answer:** how long the tunnel is expected to stay down. If the OAuth
fix is hours away, the missing third state is a nuisance. If it is days, or if the laptop is a
permanent SPOF (**B2**), the third state is the difference between serving Qwen and serving
deterministic. **This is Decision 2.**

### T4 — Does `execute_read_strict` deliver a large latency win, or nothing at all?

**Perf section:** large win — the strict read raises, `_bounded_execute_read` calls
`record_graph_failure()`, and the graph breaker finally opens on a dead Aura (**C10**).

**Outside voice:** it is a no-op — `_ReadRows.failed` is assigned and read nowhere, so the
distinction the docstring justifies it with is created and immediately discarded.

**Resolved: both are correct, about different mechanisms.** Verified by reading
`app/engines/kg_context.py:330-372`: the raise lands in `except Exception` at `:363`, which
calls `record_graph_failure()` — so the breaker really is armed, and the latency win is real.
*And* `grep -rn "\.failed" app/` returns exactly one hit, the assignment at
`kg_context.py:300` — so the `_ReadRows.failed` flag really does have zero consumers and the
stated observability defect is still live. Both belong in the report; neither cancels the
other. Recorded here rather than as a finding because it is a documentation gap on top of a
real improvement.

### T5 — Cache poisoning by leg-2 answers

**Sections:** raised the wire-invisibility of a Qwen answer (**B4** as originally scoped) but
not the cache.

**Outside voice:** `_engine_cache_key` folds in `strict` and the *configured* fallback model
name, which defaults to `""` — so the Qwen-vs-Opus distinction contributes zero bits, and a
successful leg-2 answer is cached and later served on a healthy tunnel.

**Verified and adopted into B4.** `app/routes/regenold.py:6857-6861` shows `_cacheable` gating
only on `stage2_call_failed`, confidence, and `nodes_traversed > 0`. The outside voice is right,
including its own caveat that this is currently masked by the Aura outage failing the
`nodes_traversed` term. No tension remains; credit to the outside voice for finding it.

### T6 — Is the real reliability problem in this deployment even in this diff?

**Sections:** treat Stage-2 transport as the subject and score it on its own terms.

**Outside voice:** the actual reliability problem is that Neo4j Aura is NXDOMAIN, so the graph
grounding that `AGENTS.md` invariant #3 feeds into every Stage-2 prompt is simply gone —
untouched by all 3014 lines, and (per T4) still invisible downstream.

**What would change the answer:** whether the Aura outage is a local-environment artefact or
production. If production's Aura is also dead, the grounding loss dominates any Stage-2
transport question for Answer Correctness, and the review's priority ordering is wrong. This is
a five-minute check against the deployed endpoint and should be done before acting on any of the
above. Recorded as a tension rather than a finding because it is out of this PR's scope by
construction — which is itself the outside voice's point.
