## 1. Findings

### F1 — A lever's default was flipped on a *void* measurement, and void-ness is a fact about the log

`REGENOLD_STAGE2_FULL_SYSTEM_SINGLE_TURN` rewrites the system slot **only on the
wrapper leg** of Stage-2. When the Claude-Max wrapper is down, the engine falls
back to Bedrock, and `_bedrock_complete_for_graph_rag` always receives the full
`system` — so both arms of a paired gate are byte-identical and the run can only
measure sampling noise.

A complete 95+95 paired run for this exact label was sitting on disk. Scored, it
read as a plausible **null result** (`ref_loose` −0.0035, `ref_strict` −0.0265,
p50 latency +1.39 s). The run's own log explains it: **189**
`bedrock_auto_fallback` lines. The R412 re-run carries **0**.

Severity: high, and this is the second time in two rounds that a wrong-looking
reading was nearly filed as a finding about a lever rather than about the
instrument. Netting the two: **void-ness must be read from the transport log's
fallback count, not inferred from the deltas.** Deltas from a void run look
exactly like a real null result.

### F2 — The gate PASSES, on every axis, so the default flips

n=39 of the 95-row easy split, identical rows in both arms, wrapper-served, 0
errors:

| `ref_loose` | 0.8718 | 0.9615 | +0.0897 |
| `ref_strict` | 0.4333 | 0.5831 | +0.1498 |
| `ref_conc` | 0.2025 | 0.3481 | +0.1456 |

Hard rule #8 is satisfied *with room* (`gold_dropped_head` nearly halves rather
than rising), which is the opposite of the unrestricted
`REGENOLD_STAGE2_FULL_SYSTEM` (12 → 18 on the hard split). The change therefore
keeps the unrestricted flag OFF and flips only the restricted one. Reviewed
execution: `_single_turn_full_system` is read via `os.getenv` **inside** the
call, so it is fresh per request (in-process A/B safe — which is what let the
gate measure it at all), and `history_turn_count is not None` still guards the
auxiliary callers from being treated as single-turn.

### F3 — The instrument still asserts defects the live path cannot have

`docs/measurements/r412/ref_recall_probe.py` reports **11 of 99** ref-scored rows
with an EXPECTED (gold) head that the answer prose names but the wire omits —
which reads as a pure `ref_loose`/`ref_strict` loss.

It is an artifact. The prose→reference promotion it is testing is the route's
*Component D Grounding Guard*, gated on `_stage2_landed`
(`app/routes/regenold.py`). The probe runs the deterministic path (LLM transport
pointed at a dead port), so the promotion step never executes and the omissions
cannot occur live. The live read is the gate's `ref_loose` **0.9615**.

Severity: medium (documentation/measurement integrity). The caveat is recorded in
the probe's sibling checkpoint rather than left for the next reader to rediscover.
Third instance of this class in two rounds — the probe, not the engine, is the
recurring defect.

### F5 — Real operational noise, fixed without losing the signal

The Neo4j driver logs every DBMS notification through `neo4j.notifications` at
WARNING **with the full Cypher text embedded**; our vector-recall query calls
`db.index.vector.queryNodes`, which is DEPRECATION-flagged on every execution.
Measured: the same ~1.3 kB notice three times per vector query.

`app/graph/client.py` now de-duplicates by `(classification, status_description)`
read off the `GqlStatusObject` the driver passes as the log argument — keying on
the formatted message would not work, because it embeds the query text, so every
distinct query would read as a new notification. Scope is deliberately narrow:
only `DEPRECATION`/`HINT`/`GENERIC`/`PERFORMANCE`/`UNRECOGNIZED` are collapsed;
**`SECURITY` is never de-duplicated**, so a repeated security notice cannot be
hidden by its first occurrence. Unkeyable records pass through untouched.
Idempotent install; installed before the first query.

  `enhanced.rstrip() + tail`. The gate log confirms the path is live inside 10
  rows (`stage2_truncation_guard: tail repaired`). The existing guard rejects an
  empty tail, a re-answer, an over-long tail and a still-incomplete result — but
  not a tail that starts a *new* sentence, which is the weld class observed live
  in production. A rejection rule here must survive the same "does it fire on
  passing rows" test the F7 guards failed.

  subject. Left as a recorded precision note: the intercept is benchmark-neutral
  (1/110) and the failing case is arguably still answered by the Article 50(1)
  duty to inform the *workers*. Tightening it without a measured harm would be a
  change on taste, not on evidence.
