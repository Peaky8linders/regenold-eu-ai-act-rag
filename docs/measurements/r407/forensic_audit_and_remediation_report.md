### 2.1. Scoring Definitions & Timing Constraints
Per Page 2, Table 1 of the official report:
* **Ans. Correctness (Loose):** Percentage of individual correctness criteria satisfied by candidate answers.
* **Ans. Correctness (Strict):** Percentage of questions for which **all** required correctness criteria are satisfied.
* **Ans. Conciseness:** Inverted measure of answer verbosity relative to the benchmark reference answers:
  $$\text{Ans. Conciseness} = \min\left(1.0, \frac{\text{len}(\text{reference\_answer})}{\text{len}(\text{candidate\_answer})}\right)$$
* **Ref. Correctness (Loose):** Percentage of expected references met at Article and Annex head level (e.g. `Article 6`).
* **Ref. Correctness (Strict):** Percentage of expected references met at exact subpoint level (e.g. `Article 6.1`).
* **Ref. Conciseness:** Excess references relative to expected references:
  $$\text{Ref. Conciseness} = \min\left(1.0, \frac{|\text{expected\_refs}|}{|\text{candidate\_refs}|}\right)$$
  *(Questions without annotated expected references are strictly excluded from citation metrics; n=100 reference-scored rows out of 110).*
* **Regulatory Tone:** Fraction of responses judged both appropriate and clear relative to few-shot standards.
* **Resp. Speed:** Mean per-response score:
  $$\text{Resp. Speed} = \max(0.0, 100.0 - \text{latency\_s})$$
  *(Where $\text{latency\_s}$ is the end-to-end response time in seconds).*
* **Aggregated Overall Score:** Geometric mean across all eight dimensions:
  $$\text{Overall} = \left(\prod_{i=1}^8 M_i\right)^{1/8}$$

## 5. Knowledge Graph Systems Audit: The 2-Hop Traversal Bug

A live audit of the Neo4j Aura instance (`neo4j+s://368fd9ef.databases.neo4j.io`, 1,746 nodes) revealed a critical topological bug in `app/engines/kg_context.py`:

```
                                NEO4J AURA GRAPH TOPOLOGY
   (Article) ──[:HAS_PARAGRAPH]──► (Paragraph) ──[:HAS_POINT]──► (Point) ──[:HAS_SUBPOINT]──► (SubPoint)
   [113 nodes]                     [842 nodes]                   [421 nodes]                   [68 nodes]
```

### The Bug in `app/engines/kg_context.py:202`
```cypher
_HIERARCHY_CYPHER = """
UNWIND range(0, size($ids) - 1) AS i
WITH i, $ids[i] AS aid
MATCH (a) WHERE a.id = aid AND (a:Article OR a:Annex)
OPTIONAL MATCH (a)-[:HAS_PARAGRAPH|HAS_POINT]->(u)
WITH i, a, u ORDER BY toIntegerOrNull(u.number), u.number
WITH i, a, collect(u)[..$max_units] AS units
ORDER BY i
RETURN coalesce(a.strict_citation, a.id) AS cite,
       a.title AS title,
       [u IN units | {num: u.number, text: u.text}] AS units
"""
```

**Forensic Discovery:**
1. In the database, `Article` connects **only** to `Paragraph` via `:HAS_PARAGRAPH`. Articles **never** connect directly to `Point` via `:HAS_POINT`.
2. `Point` nodes are children of `Paragraph` nodes via `(Paragraph)-[:HAS_POINT]->(Point)`.
3. Furthermore, `Point` nodes store their identifier in `.letter` (e.g. `'a'`, `'b'`), **never** in `.number`.
4. As a result, `_HIERARCHY_CYPHER` only ever retrieved top-level `Paragraph` text. Substantive obligations contained within points (e.g. Article 10(2)(a)-(g), Article 25(1)(a)-(c)) were **completely invisible to Stage-2 synthesis**, causing failures on `rg_046` and `rg_110`.

**Corrected Cypher Pattern:**
```cypher
UNWIND $ids AS aid
MATCH (a) WHERE a.id = aid AND (a:Article OR a:Annex)
OPTIONAL MATCH (a)-[:HAS_PARAGRAPH]->(p:Paragraph)
OPTIONAL MATCH (p)-[:HAS_POINT]->(pt:Point)
RETURN a.strict_citation AS article,
       p.number AS paragraph,
       p.text AS paragraph_text,
       coalesce(pt.letter, pt.number) AS point,
       pt.text AS point_text
```
