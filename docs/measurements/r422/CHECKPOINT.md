# R422 checkpoint — is the conciseness axis broken, or did the answers get longer?

**Verdict: the axis is not broken, and the regression is real and mechanical.** All
figures below are generated by
`docs/measurements/r422/conciseness_regression_attribution.py` into
`docs/measurements/r422/attribution.json` (offline measurements cost no API calls).

## 1. The metric reports what it defines

| check | result |
| :--- | :--- |
| formula | `min(1, len(reference_answer) / len(candidate))` per row, mean × 100 |
| has it changed? | no — two commits have ever touched `evals/official/rubric.py` |
| denominator stability | 649 chars mean (min 160, max 1007) on every board in `docs/measurements/r388/` |
| independent reproduction | recomputed from the R390 + R419 checkpoints joined to the gold answers: **62.02% → 44.19%**, matching the instrument exactly |

## 2. The comparison that isolates it: R390 live hard vs R419 live hard

Same 110 questions, same gold, **same generator (opus-5 over the wrapper)**.

| measure | R390 | R419 | change |
| :--- | ---: | ---: | ---: |
| mean answer chars | 1139 | 2138 | +999 |
| median answer chars | 1135 | 2239 | +1104 |
| rows grew > 15% | — | **83 / 110** | median row ratio **1.70×** |
| rows shrank | — | 6 | **4 of the 6 are the transport-degraded rows** (`rg_036`, `rg_037`, `rg_085`, `rg_092` — R420's prior-answer floor), not a shortening lever |
| rows byte-identical | — | 12 | the curated deterministic subset, ratio exactly 1.00 |
| ans_conciseness | 62.02% | **44.19%** | −17.83 pp |

Both hard turns moved (turn-1 1099 → 2154 chars; the graded pushback is the graded
answer on 110/110 rows), so this is a generation-wide change, not a retrieval one.

## 3. The denominator is calibrated; the ANSWER is flat

| | value |
| :--- | ---: |
| corr(gold criteria count, reference length) | **+0.55** (202 chars per criterion) |
| corr(gold criteria count, our answer length) | **+0.11** |
| 1 criteria (n=4) | ref 382 · answer **1122** · conc 48.6% |
| 2–3 criteria (n=57) | ref 621 · answer **2139** · conc **42.0%** |
| 4–5 criteria (n=44) | ref 683 · answer **2247** · conc 45.4% |
| 6 criteria (n=5) | ref 893 · answer **1977** · conc **54.9%** |

The axis is worst where most of the board sits (2–3 limbs), and best on the six-limb
rows only because the reference is longest there. Our answer has a large **fixed**
component. The enumeration scaffold is injected just as flatly:
`REGENOLD_CLOSED_SET_SKELETON` fires on **110/110 rows**, mean **5,125 chars**
(median 5,193), including **5,862 chars on the 1-criteria rows whose answers average
1,122 chars** (5.2× the answer it scaffolds).

## 4. Falsified: "the prompt got too big"

Measured at the provider seam on the real request path with the provider stubbed
(7-row strided sample of rows the live board actually polished: `rg_003`, `rg_028`,
`rg_052`, `rg_066`, `rg_082`, `rg_096`, `rg_110`; **both arms fired a graded Stage-2
payload on every sampled row**, so the run is non-vacuous and `comparable`):

| arm | mean Stage-2 user payload |
| :--- | ---: |
| HEAD defaults | 38,467 chars |
| the five post-R390 additions OFF | 44,997 chars |
| **delta (OFF − HEAD)** | **+6,530 chars** |

Turning the levers off makes the prompt **larger**. The smaller prompt produced the
longer answer, so the driver is the scaffold's **instruction** (show the model the
complete member list of every head it cites ⇒ it enumerates), not its size. The fix
is a generation-side, need-proportional shape contract — not prompt pruning.

Candidate set, bounded from git rather than asserted: **46 `REGENOLD_*` names exist in
`app/` at HEAD that did not at R390; 15 are default-ON** by their own literal default.

## 5. Three defects fixed (each one produced part of the misleading reading above)

* **A majority-deterministic arm is now VOID.** `gate_validity.count_deterministic_rows`
  reads each graded row's own provenance (`stage2_served_by == "deterministic"`, else
  the legacy `stage2_polish is False`) and `assess` refuses the delta. The R422 gate
  printed `answer_chars +560.9` off a baseline arm where 13 of 19 rows were Stage-1
  drafts while the transport counters read "quiet".
* **`--stride N`** (applied BEFORE `--limit`) draws a sample across the send order:
  the full 110 are 46 % easy, `--limit 40` is 68 % easy, `--stride 6` is 32 %.
* **`score_arm.load_ckpt` carries `provenance` through.** It was dropped, so the
  scoring layer could not distinguish a polished answer from a deterministic
  Stage-1 draft that happened to be graded — which is exactly how the R419 report
  under-reported the degraded rows and how a void gate reads as a result. Now the
  report names them: **4 of the 6 shrinking rows** (`rg_036`, `rg_037`, `rg_085`,
  `rg_092`), plus `rg_006` which is curated-by-design rather than degraded.
