## 1. `app/engines/task_router.py` — DELETE

**Evidence**:
- `grep "task_router"` across the repo → exactly 1 importer:
  `tests/test_task_router.py`.
- No `os.getenv("REGENOLD_TASK_ROUTER")` reader anywhere (the module
  has no env flag — it's deterministic).
- Self-described in its own docstring (line 35–38):
  > "The router does NOT change the engine's behaviour — every task
  > today still routes through `ask_compliance_question`; the dispatch
  > is **informational** (annotates the request) until we wire per-task
  > pipelines in a future round."

**Call chain**: tests/test_task_router.py → `app/engines/task_router.py`
→ dead end. The "future round" promised by the docstring never
landed in R32, R33, R34, R35, R36, R38, R39 (per CLAUDE.md).

**Why DELETE not WIRE**: the four-task taxonomy collapses cleanly back
to the existing `intent_classifier` 15-way label that IS wired
(see `app/llm/intent_classifier.py`). Wiring task_router as an
audit-chain stamp would be ~5 LOC of integration but it would
shadow the more granular intent label, not complement it. The per-
task bench-runner breakout proposed in the docstring would also fit
in `evals/bench/runner.py` directly without needing a separate router.

**LoC saved**: 218 (module) + 98 (test) = **316 LOC**.
**Risk**: low. Zero callers; tests test only the deleted module.

## 2. `app/engines/graph_aware_retrieval.py` — WIRE

**Evidence**:
- `grep` → 1 importer: `tests/test_graph_aware_retrieval.py`.
- Env flag `REGENOLD_GRAPH_AWARE` is read ONLY inside the module
  itself (`_env_enabled` at line 84). No production code reads or sets
  it.
- Module docstring (lines 44–58) explicitly says:
  > "## Wiring (NOT done in this module). The wiring step is
  > intentionally out of scope. The follow-up PR is expected to..."
  followed by THREE concrete wire points (in
  `_try_extractive_answer`, `scenario_classifier`, and a new
  `_surface_recital_anchors`).

**Why WIRE not DELETE**: this module is the largest concrete unlock
for the R35 Neo4j seed. R35 seeded 505 nodes including 180 recitals
and 68 definitions, but only the `CROSS_REFERENCES` edge type is
currently exploited (by `graph_expand_2hop`). 5 edge types remain
unused. The module already implements the three highest-leverage
traversals (`lookup_definition_by_term`, `recitals_for_article`,
`obligations_for_role`) with full timeout + existence-gating + 745
lines of tests passing. The wire-up is small (the docstring lists
three specific file:function targets — all in code we control).

**Suggested wire-point (one paragraph)**: in
`app/routes/regenold.py::_try_extractive_answer`, BEFORE the existing
`select_definition_sentence` call (around line 444), add a
`lookup_definition_by_term(question)` call gated on
`is_enabled()`. The function returns `None` when the env-gate is off
OR the graph is down, so the route stays sub-µs in the default
config. This is symmetric with the existing `vector_rerank` wire-up
pattern at line 477.

**LoC**: 689 (module) + 745 (test). Test debt is real but the tests
are well-isolated (mock GraphClient throughout) and would survive
unchanged after wiring.
**Risk of deletion (i.e., if we abandoned the module)**: low — no
production callers — but we'd be throwing away the highest-ROI
unwritten code in the repo. The R35 graph seed becomes mostly
ornamental without this.

## 3. `app/engines/cross_encoder_rerank.py` — DELETE

**Evidence**:
- `grep "cross_encoder_rerank"` → 2 files: the module itself and
  `tests/test_cross_encoder_rerank.py`. No production importer.
- Env flag `REGENOLD_CROSS_ENCODER_RERANK` is read ONLY inside the
  module (line 158). No production code sets or reads it.
- CLAUDE.md (Round 32 section on Layer D): "The rerank is wired
  only as a scoring helper in Round 32; the full route integration
  is deferred to Round 33 once the bench-side gate tuning lands."
  R33 shipped failure-driven scenario coverage instead. R34
  shipped scope.py fixes. R35 shipped Neo4j. The wire never landed.

**Why DELETE not WIRE**: per CLAUDE.md Round 32, an earlier first-cut
fusion of rerank + dense traded "+0.028 Conciseness for -0.020
Strict Ans — net negative on the rubric weights." The Round-32
post-mortem itself concluded the module is "precision-positive only
when fused with neural endorsement" — i.e., it needs the BGE ONNX
Strategy-B model that was never bundled. Strategy-A alone (the only
working code-path) was deemed bench-negative. Without an ONNX asset
ship, this is dead weight. If the project ever wants neural rerank,
the right path is to start from `embeddings_index.py` (which IS
wired) and add a true cross-encoder there.

**LoC saved**: 917 (module) + 512 (test) = **1,429 LOC** — the
largest single deletion.
**Risk**: low. Zero callers, bench-negative when last measured, and
the underlying use case (dense rerank) has a competing wired solution.

## 4. `app/data/eu_ai_act_tree.py` — WIRE

**Evidence**:
- `grep "eu_ai_act_tree"` → 1 importer: `tests/test_eu_ai_act_tree.py`.
- No env-gate flag exists for this module (it's data, not a feature).
- CLAUDE.md (Round 32 table): "Layer A: Built (1426 nodes), wire
  deferred." Round 33+ never wired it.

**Why WIRE not DELETE**: this is the **EUR-Lex prose re-parsed into a
1,426-node hierarchical tree** with stable, deterministic node IDs.
Three downstream features want a tree:

1. The `sentence_index.py` length-gate fix from R34 (raised 500→1000
   chars to capture leading paragraphs) is a workaround for not
   having paragraph-level child nodes — the tree would let us pick
   the actual paragraph-1 node directly instead of regex-splitting
   prose at runtime.
2. `graph_aware_retrieval` (module #2) wants paragraph-level
   metadata (`paragraph_number`, `subpoint_letter`, `risk_tier`) to
   attach finer-grained citations.
3. Audit-chain entries currently store article-level refs; tree
   node ids would enable paragraph-level forensic replay.

**Suggested wire-point**: lazy-import `build_tree()` inside
`app/engines/sentence_index.py::select_answer_sentence` and use
tree.iter_children() over an article node instead of regex-splitting
`ARTICLE_FULL_TEXT[article_ref]`. Pure swap-in — same return shape,
same BM25 ranker, but the candidate set comes from typed tree nodes
instead of regex splits. Catches the EUR-Lex enumeration edge cases
the R34 length-gate fix is currently papering over.

**LoC**: 856 (module) + 429 (test). The tree builder has 52 passing
tests — it's mature, deterministic, and idle.
**Risk of deletion**: low (no callers) — but it's a high-quality
substrate for two adjacent features the project actively wants.

## 5. `app/engines/vector_rerank.py` — KEEP-AS-IS

**Evidence**:
- `grep` shows `app/routes/regenold.py:477`:
  ```python
  from app.engines.vector_rerank import (
      is_enabled as _vrr_enabled,
      rerank_sentences as _vrr,
  )
  if _vrr_enabled():
      fused = _vrr(question, ref, sentence)
  ```
  This is inside `_try_extractive_answer`, the live wire path.
- The CLAUDE.md "29% test coverage" claim refers to the
  `tests/test_vector_rerank.py` 7-test file. Coverage is low BECAUSE
  the module's heavy paths require Linux-only turbovec wheels and
  on-disk ONNX assets that the Windows dev box can't generate. The
  passthrough/disabled paths ARE covered.

**Verdict**: the original audit prompt's suspicion is wrong here —
this module IS wired to production. The audit-claim "no mock-asset
test path" is fair (the assets paths are untested) but the env-off
fallback path that runs on every Windows + Railway request IS
covered, and the wire-up itself is exception-swallowed (route line
485–486 wraps the whole rerank in `try/except: pass`).

**LoC**: 274 (module) + 82 (test). Keep.
**Risk if mis-classified**: high — deleting this would break the
opt-in Linux production rerank path documented in CLAUDE.md Round 27.
